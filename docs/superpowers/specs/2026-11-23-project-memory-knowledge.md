# 프로젝트 메모리 · 지침 · 지식 폴더 · 앱 아이콘 — 설계

날짜: 2026-11-23 · 상태: 사용자 결정 반영(2026-11-23) · 앞선 설계: `2026-11-23-any-lm-desktop-design.md`

## 1. 사용자 결정

| 항목 | 결정 |
|---|---|
| 메모리 | 모델과 사용자가 함께 쓴다. 모델은 `remember` 도구로 저장, 사용자는 메모리 패널에서 보기·추가·편집·삭제. 프로젝트의 모든 대화에 들어간다. |
| 지식 | 프로젝트에 지식 폴더를 추가하면 앱이 글을 조각내 색인한다. 질문마다 관련 조각을 찾아 프롬프트에 넣고, 모델은 `search_knowledge` 도구로 더 찾을 수 있다. |
| 지침 | 프로젝트 화면에 전용 지침 편집기(큰 입력란, 서식 예시, 글자·토큰 수). |
| 아이콘 | 연결된 노드 + 대화 말풍선. 둥근 사각형 안. 작은 크기에서도 읽히는 단순한 도형. |

## 2. 공통 원칙

- 프로젝트 모드(프로젝트·코드 화면)에서만 동작한다. 일반 채팅은 바뀌지 않는다.
- 프롬프트에 넣는 양은 로드된 컨텍스트에 비례한다. `ctx_chars = context_length × 1.5`(전역 상수 `CHARS_PER_TOKEN`).
- 지식 폴더는 **읽기만** 한다. 앱은 지식 폴더에 아무것도 쓰지 않는다.
- 저장 데이터는 serde 기본값으로 옛 데이터와 호환된다(필드가 없으면 빈 값).
- 내부 이름 규칙(exaone.rs 등 유지), 화면 문구 한국어, 브랜드 문구 금지 규칙은 그대로.

## 3. 프로젝트 메모리

- 저장: `Project.memory: Vec<MemoryItem>`; `MemoryItem { id, text, created_at, updated_at, source: "model" | "user" }`.
- 한도: 항목 하나 `MEMORY_ITEM_MAX_CHARS = 500`자, 프로젝트당 `MEMORY_MAX_ITEMS = 200`개. 넘으면 저장을 거부하고 이유를 돌려준다(모델에게도).
- 모델 도구 `remember { text }`: 승인 없이 바로 실행. 앞뒤 공백 정리, 이미 같은 문장이 있으면 새로 만들지 않고 "이미 기억하고 있습니다". 결과는 도구 카드로 보인다.
- 시스템 프롬프트 `[프로젝트 메모리]` 절: 항목을 오래된 순으로 `- ` 목록. 예산 `memory_budget = min(6_000, ctx_chars × 0.08)`자. 넘치면 오래된 항목부터 빼고 "(오래된 메모리 n개 생략)"을 적는다.
- 프롬프트 안내 한 줄: 사용자가 기억하라고 하거나, 다음 대화에도 필요한 사실(선호, 결정, 용어, 마감)을 알게 되면 `remember`로 짧게 저장하라. 대화 내용 전체나 파일 내용을 저장하지 말라.
- 명령: `add_project_memory`, `update_project_memory`, `delete_project_memory` (모두 `Project`를 돌려준다).
- 화면: 프로젝트 화면에 "프로젝트 메모리" 카드 — 목록(출처 표시: 모델/직접), [추가], 항목별 편집·삭제, 개수/글자 수. 모델이 저장하면 목록이 바로 갱신된다.

## 4. 프로젝트 지침 (전용 편집기)

- 저장 위치는 지금처럼 `Project.instructions`(형식 변경 없음).
- 프로젝트 화면의 지침 카드에서 [편집]을 누르면 전용 편집기(큰 모달 또는 패널): 입력란 최소 14줄, 글자 수 · 약 토큰 수(1.5자/토큰) · 지금 로드된 컨텍스트 대비 % 표시, 10%를 넘으면 노란 경고.
- [서식 예시] 메뉴로 예시 지침을 넣는다(비어 있으면 넣기, 내용이 있으면 끝에 덧붙이기): 보고서·문서 작성, 코딩, 자료 조사·요약, 번역·교정. 예시 문구는 한국어, 브랜드 없음.
- 저장·취소. 저장은 기존 `create_or_update_project` 경로.

## 5. 지식 폴더

- 저장: `Project.knowledge_folders: Vec<String>`(절대 경로). 색인은 앱 데이터 폴더 `knowledge/<project_id>.json`.
- 색인 단위: 파일 → 글 추출 → 조각 `CHUNK_CHARS = 1_200`, 겹침 `CHUNK_OVERLAP = 200`(문단 경계 우선). 조각 `{ path, chunk_index, text }`, 파일별 `{ path, size, mtime, chunks }`.
- 대상 파일: 텍스트(.md .txt .csv .tsv .json .yaml .yml .xml .html .htm .log, 소스 코드 확장자), 문서(.docx .hwpx .pptx .xlsx .pdf)는 `read_file`과 같은 추출 경로. 건너뛰는 폴더: `.git node_modules target dist build .venv venv __pycache__ .next`. 한도: 파일 `KNOWLEDGE_MAX_FILES = 3_000`개, 텍스트 파일 5MB, 문서 파일 30MB. 넘거나 못 읽은 파일은 건너뛰고 개수를 보고한다.
- 검색: BM25. 토큰 = 영문·숫자 단어(소문자) + 한글은 2글자 묶음(bigram). 결과는 조각 텍스트 + 출처 경로 + 점수.
- 색인 갱신: 폴더를 추가할 때, [다시 색인] 버튼, 그리고 턴 시작 때 빠른 갱신(파일 크기·수정 시각이 바뀐 것만 다시 추출, 5초 넘으면 남은 것은 다음으로 미룸). 색인 중 상태와 결과(파일 n개 · 조각 n개 · 건너뜀 n개 · 마지막 색인 시각)를 화면에 보인다.
- 자동 참고: 프로젝트 모드에서 사용자 메시지를 질의로 상위 조각을 고른다. 예산 `knowledge_budget = min(12_000, ctx_chars × 0.15)`자, 최대 6조각. 시스템 프롬프트 뒤 `[참고 자료]` 절에 `### 출처: <경로>` + 조각. 안내: 참고 자료가 질문과 관련 있으면 활용하고 출처 경로를 밝혀라, 관련 없으면 무시하라.
- 모델 도구 `search_knowledge { query, top_k? }`(top_k 기본 5, 최대 10): 승인 없이 실행, 결과 상한은 도구 출력 상한(`tool_output_cap`)을 따른다. 지식 폴더가 없으면 도구를 목록에 넣지 않는다.
- 명령: `add_knowledge_folder { projectId, path }`, `remove_knowledge_folder`, `reindex_knowledge { projectId }`, `knowledge_status { projectId }`.
- 화면: 프로젝트 화면 "지식 폴더" 카드 — 폴더 목록(경로, 파일·조각 수), [폴더 추가](폴더 고르기 대화상자), [제거], [다시 색인], 상태 줄. 답변의 도구 카드에서 `search_knowledge` 결과를 볼 수 있다.

## 6. 앱 아이콘

- 원본 SVG: `src-tauri/icons/icon.svg` (1024×1024). 둥근 사각형 배경(그라데이션), 서로 선으로 이어진 노드 3~4개, 그 위 말풍선 하나. 16px에서도 형태가 보이게 선을 굵게, 세부를 적게.
- `npx tauri icon src-tauri/icons/icon.svg`로 모든 크기(ico, icns, png, Square*)를 다시 만든다.
- 앱 안의 로고(사이드바의 "LM" 글자 상자)를 같은 그림의 작은 SVG 컴포넌트로 바꾼다.

## 7. 완료 기준

1. 모델이 `remember`로 저장한 메모리가 메모리 패널에 보이고, 새 대화의 시스템 프롬프트에 들어간다. 사용자가 편집·삭제할 수 있다.
2. 지침 편집기에서 서식 예시를 넣고 저장하면 시스템 프롬프트에 반영되고, 글자·토큰 수가 보인다.
3. 지식 폴더를 추가하면 색인되고, 그 폴더 문서에만 있는 내용을 물으면 답에 그 내용과 출처 경로가 나온다(실측: 9B, 32K).
4. 실행 파일·창·작업 표시줄 아이콘이 새 아이콘이다. 사이드바 로고도 같다.
5. 세 검증 명령 통과, 새 기능마다 단위 테스트.
