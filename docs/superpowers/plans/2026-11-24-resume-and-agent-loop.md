# 개발 서버·미리보기와 에이전트 루프 구현 계획

> **실행 방식:** AGENTS.md의 순서대로 검증하고, 작업 단위마다 STATUS·LOG 갱신과 커밋을 한다.

**목표:** 개발 서버 T2/T3 인계를 마치고, Any LM Desktop의 원본 의존 이름을 정리하며, 작업이 많은 턴도 고정 도구 라운드 상한 없이 진행한다.

**구조:** 기존 ConPTY 관리자에 프로젝트별 개발 서버를 연결한다. 기존 LM Studio 스트림 루프와 하니스는 공유 진입점을 유지한다. 모델 요청의 오래된 도구 교환만 줄이고 앱에 저장되는 작업 기록은 보존한다.

**설계:** `docs/superpowers/specs/2026-11-24-dev-server-preview-console.md` 및 사용자 요청(2026-11-24).

## 공통 제약

- 원본 저장소와 데이터는 독립적으로 유지한다. 기존 사용자 데이터와 승인 정책, 취소, 모델 요청 제한 시간은 보존한다.
- 프런트엔드와 Rust의 저장 및 호출 자료형을 함께 갱신한다.
- 작업마다 npm 테스트, TypeScript 검사, Rust 라이브러리 테스트를 실행한다.

## 작업

- [x] 인계 문서에서 이미 생성된 원격 저장소 및 실제 포트 설정을 반영한다.
- [x] `exaone.rs` 루프에서 50 라운드 상한을 제거한다. 모의 LM Studio의 55회 파일 읽기와 최종 응답, 컨텍스트 압축 뒤 도구 요청·결과 ID의 일치, 중지 처리 및 승인 후 재개를 확인한다.
- [ ] 원본 명칭이 남은 백업·임시 경로, 자격 증명, 생성 문서, 테스트 등 현재 동작을 조사한다. 기존 Any LM 사용자 데이터와 라이선스 출처를 보존한다.
