# 0001. 원본 저장소를 이력째 복제해 시작한다

- 날짜: 2026-11-23
- 상태: 확정 (사용자가 A를 선택)

## 무엇을
K-EXAONE Desktop(`C:\DOCS\EXAONE`, 커밋 `e885b02`, 0.4.4)을 `git clone`으로 이력째 복제해 `C:\DOCS\any-lm-desktop`를 만들고, 원본을 `upstream` 원격(push 주소 `DISABLED`)으로 연결한다.

## 검토한 방법

| | 방법 | 장점 | 단점 |
|---|---|---|---|
| **A (선택)** | 원본 git 저장소를 이력째 복제하고, 원본을 `upstream` 원격으로 연결 | 원본의 공통 버그 수정을 `git cherry-pick`으로 가져올 수 있다. 다음 도구가 커밋 이력으로 코드의 이유를 알 수 있다 | 이력에 EXAONE 기록이 남는다(비공개라 문제없음) |
| B | 현재 소스만 복사해 커밋 하나로 새 저장소 | 깨끗한 시작 | 원본 수정을 옮길 때마다 수작업 비교. 두 앱이 코드 대부분을 공유하므로 부담이 계속 쌓인다 |
| C (제외) | 원본 저장소 하나에서 설정으로 두 앱을 나눔 | 코드 한 벌 | "별도 프로젝트"라는 요청과 맞지 않고 구조가 복잡해진다 |

## 왜 A인가
- 두 앱이 코드 대부분을 공유하므로 원본의 버그 수정을 계속 가져올 수 있어야 한다.
- Claude Code, Codex, Antigravity가 번갈아 작업하므로 커밋 이력이 코드의 이유를 알려 주는 맥락이 된다.
- 이력에 EXAONE 기록이 남는 단점은 저장소가 비공개라 문제가 되지 않는다.
